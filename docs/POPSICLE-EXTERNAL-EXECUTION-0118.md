# 0118 External provider return boundary for IPCI SSR

An extra self-reference released at the end of a WLAN function still leaves a WLAN return instruction. The external provider now owns the IPCI SSR shutdown/reinit entry points. Patch 0049 installs these provider function pointers directly into the native ICNSS callback table. The provider obtains a WLAN module reference under its registration mutex, copies the callback, increments in-flight accounting, unlocks, and calls the existing complete native PLD callback. Only after every WLAN frame returns does provider code decrement the counter and release that execution reference. It then returns directly to the external ICNSS framework.

The provider copies the registration descriptor into its own storage and never retains the caller's descriptor address. It does not take a permanent WLAN registration reference that would prevent ordinary module unload. Instead, registration/unregistration must occur while WLAN code/data are live. Module exit closes admission before native ICNSS unregister, which must drain framework callbacks before the WLAN module and its dependency on provider can disappear. Callback acquisition racing module GOING refuses without calling WLAN. Real loader and ICNSS drain contracts are still required; the modeled tests do not independently prove them.

Exact duplicate registration returns EALREADY, avoiding accidental removal of an earlier registration when a second native register fails. Foreign owners cannot close/unregister another channel. Closing admission is sticky while a callback is active: close/unregister return EBUSY, preserve descriptors, and reject later entry. No wait is held across callback execution. An explicit unload may retry once the active callback returns; no automatic retry scheduler or reopen API is installed. Native registration-error rollback is tested for a synchronously drained failure only; asynchronous init failure and native error-path drain are not certified.

The existing upper driver-unload preflight now closes this execution channel after private owner/journal admission succeeds and before unload flags, native bus unregister and global teardown. The native PLD unregister repeats that close check and retains the registration on busy/error. Its void return still cannot by itself stop a caller that bypasses upper preflight. The public native callback ABI and the existing PLD callback bodies are preserved.

## Verification checkpoint

Local Python tests, syntax, full native IPCI source restoration, host/external fixture assembly and patch forward/reverse checks passed. Native C execution and target module linking require Actions and are not claimed yet. A dedicated fixture executes production provider code, complete native IPCI registration/unregistration/reinit/shutdown functions, and the actual native slot/descriptor changes. It checks module refusal, descriptor copying, duplicate/foreign ownership, native registration rollback, callback errors, shutdown/reinit final private-reference release and a real pthread callback-versus-close overlap. Five external mutation controls target missing acquire, missing put, put before return, ignored closing and ignored in-flight drain. The actual native upper unload prefix also executes with a modeled provider close result: two hard/soft caller cases and a mutation verify that EBUSY is propagated before teardown and restores the soft-unload flag.

Module-loader operations, ICNSS framework registration/unregister drain, HDD callbacks and synchronization are modeled. Native DSC, kernel unload races, physical remove and firmware are not executed. The external provider remains a distinct linked module; full import/CRC gates must verify that the WLAN's new functions resolve to that module rather than stock CNSS.

## Remaining limits

This protects WLAN return frames for IPCI SSR shutdown/reinit. It does not wrap native remove, crash shutdown, PM, idle, other bus callbacks or all autonomous work; those retain their original lifetime contracts. Managed metadata self-detach also needs its own caller audit. Neither a void callback nor this channel can veto forced module unload or hardware disappearance. Native ICNSS unregister must finish external callback return before the WLAN's provider dependency is released. Radio activation remains disabled. No phone operation, Apple discovery, handshake or file transfer was tested.
