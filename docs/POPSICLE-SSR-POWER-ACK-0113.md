# 0113 Native reinit admission with power-stop completion

Patch 0045 connects the native recovery reinit callback to the explicit 0112 module continuation. Under the resumed original PSOC transition, a blocked private stop looks up the HDD, checks the callback device, and calls `hdd_mishare_resume_shutdown()`. That power-layer function first requires a successful native module continuation, then executes the same LPASS notification and SMMU completion tail used by ordinary `hdd_wlan_shutdown()`. ACK here means return from the existing native power tail, not a separately verified LPASS/firmware acknowledgement. Only a successful return from both steps clears the SoC stop gate and admits native reinit.

Each native reinit callback performs at most one qualified module poll. Pending and hard failures retain the stop gate and the original transition, report the actual error through start-complete, and never enter the probe/reinit body. No new worker, timer, blocking retry loop or platform retry policy is installed. A future callback can poll an eligible wait; a permanent failure cannot be reset. Keeping the transition active deliberately prevents ordinary operations from entering a partially stopped private context. Physical-remove/exit orchestration is still incomplete and must not be treated as supported.

An empty module journal is not a completion receipt. If a standalone module continuation already consumed it, the upper path returns ENOENT and retains its gate. Missing HDD, callback-device mismatch, changed native parents/status, unsupported mode and expired recovery state also refuse admission. The journal still holds borrowed identities rather than HDD/component leases. The caller/framework must retain the native lifetime contract across callbacks.

After a successful power ACK, native reinit may itself fail. The callback retains the fact that this was a private continuation and reports that reinit error even though the stop gate has correctly cleared. Ordinary non-private status handling remains unchanged.
